# TRUST / FALL

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

2〜6席で遊べる、22種類のブラウザー向け心理戦・交渉ゲーム集です。交渉し、行動を秘密に選び、全員で結果を確認しながら、3・5・7ラウンドで得点を競います。公開リンクと5文字のルームコードを共有すれば、別々の端末から同じテーブルに参加できます。アカウント登録は不要です。

> このページは日本語のプロジェクト紹介です。ゲームの画面表示は現在英語です。

## 今すぐ遊ぶ

[TRUST / FALLを開く](https://trust-fall-table.actionintime.chatgpt.site) · [GitHub Pagesの入口](https://wuisabel-gif.github.io/trust-fall/)

GitHub Pagesは、`gh-pages`ブランチにある公開ゲームへの転送ページです。実際のマルチプレイヤー同期と得点計算は、ゲームのバックエンドで処理します。

1. 8種類のキャラクターから外見を選び、名前を入力してテーブルを作成します。
2. 友達は名前と5文字のルームコードを入力し、**Join table**を押します。招待リンクならコードが自動入力されます。
3. ホストがモード、ラウンド数（3・5・7）、交渉時間（30・45・60・90秒）を選びます。全員が **I’m ready** を押したら、ホストが **Start game** で開始します。
4. チャットで交渉し、行動を秘密に確定します。一斉公開後、サーバーが得点を更新します。終了後はホストが再戦を開始できます。

![ゲームの入口](docs/screenshots/01-entry.png)
![ルームコードで参加](docs/screenshots/02-join-room.png)
![モード選択と待機室](docs/screenshots/11-lobby-cards.png)

待機室の **Change character** で外見を変更できます。変更は全員に反映され、自分の準備状態が解除されます。同じ外見のプレイヤーは席番号と「shared look」で区別されます。モードや試合設定を変更した場合も、再度準備が必要です。

## 交渉・評判・振り返り

交渉中は **Send to** で相手を選ぶと、1対1のメッセージを送れます。サーバーは送信者と受信者にのみ内容を返し、結果公開後も他のプレイヤーには見せません。AIは個別メッセージには反応しません。

キャラクターの下にある履歴の点は、協力（金）、裏切り（赤）、その他の行動（中間色）、未提出・観戦ラウンド（白抜き）を表します。点にカーソルを合わせるかフォーカスすると詳細が表示されます。

![秘密の行動とチャット](docs/screenshots/04-gameplay.png)

試合終了後は、各ラウンドの行動・対象・得点変動を振り返れます。協力、裏切り、得点の変動幅などの表彰もあります。「Biggest swing」は、連続する2ラウンドの獲得点の差が最大だったプレイヤーです。協力・裏切りの表彰はTrust / FallとThree Applesが対象で、同率の場合は複数人が受賞します。

![試合終了後の振り返り](docs/screenshots/12-match-recap.png)

途中参加や満席の場合は観戦できます。観戦者は公開チャットと結果を確認できますが、発言や行動はできません。再戦時は待機順に人間のプレイヤーが優先され、まずAIの席と交代します。人間で6席が埋まっている場合は空きを待ち、待機室で **Take a seat** を選びます。観戦は最大20人です。

## モードと得点

22種類のモードには、それぞれゲーム内説明、秘密の選択、サーバーによる採点、AIの戦略があります。詳しくは[モードの改編について](docs/game-modes.md)（英語）をご覧ください。短時間で遊べる独立したアレンジであり、漫画の大会全体を再現したものではありません。原典のルールが不足するモードは、オリジナル設計であることを明記しています。

進行：作成・参加 → 準備 → 開始 → 交渉 → 行動の確定 → 結果公開 → 12秒の休憩 → 次のラウンド → 勝者発表 → 再戦。

基本モードのTrust / Fallでは毎ラウンド組み合わせが変わり、相手のいない観戦役は0点です。双方が協力すると各30点、一方だけが裏切ると裏切った側が50点、相手が0点、双方が裏切ると各5点になります。

全モード共通で、時間内に行動を提出しなかった場合は−10点です。自動的に行動が選ばれることはありません。一度も行動を提出していないプレイヤーは優勝できず、最高点が同じ場合は同時優勝となります。

## AIと1人で練習

6人を集める必要はありません。モードごとに最低2席または3席が必要ですが、AIも人数に含まれます。

1. テーブルを作成し、モードを選びます。
2. **Add AI player** で1人追加するか、**Fill empty seats with AI** で空席を埋めます。
3. **I’m ready** を押してゲームを開始します。

AIは自動で準備完了になり、ホストは待機室で削除できます。人間とAIを混ぜて遊ぶこともできます。

AIは内蔵の戦略プログラムです。過去に公開された行動や順位を参考に選択し、性格別の台詞や状況に応じた反応を使います。直近の台詞や同じラウンド内の重複を避けます。現在の人間の秘密の選択を参照することはできません。外部AI APIやAPIキーは不要です。

## 技術構成

React / Vinextクライアント → 同一オリジンのゲームAPI → Cloudflare D1。

サーバーがルーム、タイマー、組み合わせ、行動、得点を管理します。ブラウザーは約900ミリ秒ごとに状態を取得し、別端末でも同じ状態を共有します。CASによるバージョン確認で、同時操作による上書きを防ぎます。

席の認証情報はsessionStorageに保存します。APIは相手の秘密の行動や認証情報を返しません。ルームは24時間後に期限切れとなり、新しいテーブルを作成するときに24時間以上更新されていない記録を削除します。

## ローカル開発と検証

依存関係をインストールし、`npm run dev`の前に、コミット済みのデータベースマイグレーションをローカルD1へ適用してください。スキーマを変更した場合は`npm run db:generate`でマイグレーションを生成します。本番への公開時はSitesがコミット済みマイグレーションを適用します。

```sh
npm ci
# コミット済みのマイグレーションをローカルD1に適用してから実行
npm run dev
```

```sh
npx tsc --noEmit --incremental false
npm run test:game
npm run test:api
```

ゲームのテストは全モード、対応ラウンド数、合法手、AI、秘密情報、時間切れ、得点、表彰、観戦者の再戦参加を確認します。APIテストはメモリー上のSQLiteと実際のルート処理を使い、古いルームの削除、同時参加、CAS再試行、認証、個別メッセージの分離を検証します。

ブラウザーテストでは、デスクトップ・スマートフォンサイズの独立したセッション、チャット同期、秘密の選択、確定後の変更防止、得点、再読み込み、試合全体、再戦を確認しています。3クライアントのテストでは個別メッセージ、観戦、設定、振り返りも確認しています。実機や大規模な同時接続の負荷試験は未実施です。
